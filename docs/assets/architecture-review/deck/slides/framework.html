Microsoft Agent Framework

It runs the tool-calling loop; the rest is structure

The part that matters

ChatClientAgent

Sends the prompt with the tools, runs the C# tool on each call, and repeats until the JSON reply. Keeps the session for the repair request and sums the tokens.

Structure

WorkflowBuilder

Wires context → review → validation with typed hand-offs and failure events. Linear today: three method calls would do the same.

Not the framework

IChatClient

Microsoft.Extensions.AI: the provider abstraction that swaps OpenAI, Azure OpenAI and Anthropic.

Not used: multi-agent orchestration, persistent memory, hosted agents.

Microsoft.Agents.AI and Microsoft.Agents.AI.Workflows 1.26.0 · ADR-004 · 8

Without ChatClientAgent the function-calling loop would be hand-written: send the request with the tool definitions, detect tool calls in the reply, invoke RepositoryTools, append the results, and call again until a final text. The agent also keeps the session, which is how the one repair request reuses the same conversation, and aggregates usage across calls. WorkflowBuilder with InProcessExecution gives the three steps typed inputs and outputs and surfaces ExecutorFailed and WorkflowError events; for a linear pipeline it is organization rather than capability, and it leaves room for parallel steps or more agents later. Provider portability comes from Microsoft.Extensions.AI’s IChatClient, not from the Agent Framework.
