The review never fails the PR’s other checks · 16

Coverage has three states: complete, incomplete (with reasons) and failed (with one reason). Incomplete still reports bugs. A failed commit listing does not stop the review: the language falls back to the description and the language input, with a warning in the log. A GitHub API error while reading the pull request itself ends the review job with exit code 1 and no result, so the workflow run fails and nothing is posted. Jira failures name the cause without the provider’s text.
