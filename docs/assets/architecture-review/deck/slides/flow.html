Runtime flow

One review in eight steps, with the LLM in only one

1

Trigger

ready for review, or @integricode review

2

Gate

forks and non-writers stop; no secrets

3

Install

integricode 1.* from GitHub Packages

4

Read the PR

PR, files and commits via the REST API

5

Requirement

REQ entry or Jira issue; picks en or pt-BR

6

Review · LLM

context → agent → validation

7

Hand-over

result.json as a workflow artifact

8

Publish

summary, inline findings, stale ones minimized

Measured on the first adopter (v1.1.1): review job 25 s, comment job 16 s.

Steps 1–7 run in the review job; step 8 in the comment job · 4

Step 2, the gate, reads the event file without any secret: forks are skipped by policy, and comments from users without admin, maintain or write permission are ignored. Step 3 installs the tool with the caller’s own GITHUB_TOKEN. Step 5 finds the first REQ-NNN or Jira key in the title, branch, then description, and picks the review language from the description and commit subjects. Step 6 is the only step that calls the model. Step 8 runs in a separate job with write access and no secret; if a commit arrived meanwhile, it posts nothing and the summary says superseded.
